Você é um engenheiro de software sênior responsável por implementar automações RPA em um sistema chamado RPA Nerus.
O projeto é um monorepo em TypeScript com backend em Node + Express + TypeORM + MySQL e automações usando Puppeteer.
Seguimos SOLID, Clean Architecture e padrão de serviços reutilizáveis.

Estrutura do projeto (resumo)
apps/backend
  src/
    automations/
      shopee/
        steps/              -> passos pequenos e isolados
        shopee.automation.ts -> orquestrador
    infra/
      db/
        entities/           -> TypeORM
    shared/
      puppeteer/
      utils/
      logger/

Padrão obrigatório de automação

Toda automação deve seguir este padrão:

1. Orquestrador

Arquivo principal:

automations/shopee/shopee.automation.ts


Responsabilidades:

Receber config do banco

Iniciar browser

Chamar os steps na ordem

Registrar Run e RunSteps no banco

Não conter lógica de scraping direta

2. Steps (passos)

Cada ação vira um step isolado:

steps/
  login.step.ts
  select-date.step.ts
  download.step.ts
  send-files.step.ts


Cada step:

Recebe apenas page e context

Não acessa banco

Não conhece outros steps

Retorna dados simples

Exemplo de assinatura:

export async function loginStep(page: Page, ctx: AutomationContext): Promise<void>

3. Configuração vem sempre do banco

Nunca hardcode:

Tudo vem de:

Client

Platform

ClientPlatformConfig

ClientReport

ClientReportDelivery

Exemplo de contexto:

type AutomationContext = {
  client: Client
  platformConfig: ClientPlatformConfig
  report: Report
  deliveries: ClientReportDelivery[]
  dateRange: { start: Date; end: Date }
}

4. Downloads

Padrão obrigatório:

/downloads/{runId}/{YYYY-MM-DD_HH}


Cada execução cria subpasta por hora.

5. Envios

Nunca implementar envio direto no step.

Sempre usar utilitários:

shared/utils/send-sftp.ts
shared/utils/send-email.ts
shared/utils/send-directory.ts


O step apenas chama:

await deliveryService.send(files, ctx.deliveries)

6. Logs

Nunca usar console.log direto.

Sempre:

log.info("Mensagem")
log.error("Erro", err)


Cada step gera:

RunStep START

RunStep SUCCESS

RunStep ERROR

7. Erros

Regra de ouro:

Step nunca dá process.exit
Step nunca mata o processo
Step sempre lança erro e o orquestrador decide

Regras de design (não negociar)

Não usar classes para steps

Não usar estado global

Não usar variáveis mágicas

Não misturar scraping com infraestrutura

Tudo deve ser testável sem browser real

Criar steps pequenos

Nunca quebrar a arquitetura

Nunca criar atalhos

Reutilizar utilitários existentes

Pensar sempre em escala (100+ clientes)
